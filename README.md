# 拼装模拟器

《炉石传说：黑暗帝国的统治》“拼装”机制的非官方交互模拟器。直接打开 `index.html` 即可体验；13 张来源卡、候选卡图与运行所需数据都在仓库中。

> 这是依据试玩服标签和卡牌资料制作的模拟，具体候选池、配对规则和出现概率仍可能与正式游戏不同。

打开 `index.html` 即可使用。页面可选择《黑暗帝国的统治》的 13 张拼装卡，切换中立卡的玩家职业，重新掷出组合，并选择组件的上半段或下半段描述。操作台在原卡牌上叠放两段文本框，保留卡牌底部的攻击力、生命值或武器耐久度。选中的组件文本会在两边和主体上标亮；点击主体上被替换的文本即可撤回。重新拼装时会先加载卡图，再一起显示新组合。主体只会是随从；组件可以是表格中的随从、法术、武器等卡牌。普通拼装的成品会保留主体的卡名、插画、种族和稀有度；来源卡明确给予的减费或属性加成另行显示。

拉夏使用用户指定的 14 张专属牌：其中 13 张随从可作主体，昆虫利爪作为武器只能作组件。因为这套牌横跨 2 至 7 费，模拟器对拉夏不施加普通组件费差，以便大法师安东尼达斯也能成为主体；这项特殊费用处理尚待试玩服验证。拉夏不限组件职业；结果使用客户端中的“阳炎耀光”被动英雄技能外观，不显示原随从的费用和属性，并将少量只适用于随从的字眼改为英雄技能语境。

组件来自制作时使用的 `拼装组件.xlsx`。表格有 321 行，按卡名合并同名记录后为 259 张候选卡。生成好的 `data.js` 和完整卡图已包含在仓库中，运行模拟器不需要原表格。`build_data.py` 是数据维护脚本；若要重新生成数据，需另外准备原表格和脚本中注明的新卡缓存。`download_card_images.py` 可继续下载缺失卡图，已有图片会跳过。

模拟按试玩服 37.0.0.253957 的标签筛选组件（4533）、排除不可作主体的随从（4546），并将仅作主体的随从（4547）移出组件池；标签快照在 `client_tags.json`。表格中的“原始石牙兽”“泽奥图”没有 4533，故不再作为组件。之后按公开说明筛选玩家职业及组件费用；“错位拼配者”和“暗影匠师”适用各自的特殊条件。已过滤同名和相同描述，并按机制勘误阻止“侏儒嚼嚼怪”“石头穴居人”与亡语主体配对。会排除亡语后让已死亡的本随从加属性、随机攻击或召唤自身复制等无效拼法；只有上下两段都可用的组件才会出现在界面。

根据试玩服研究，4578 表示不能与另一张自带回合结束触发效果的牌配对，方向对调也一样；模拟器用卡牌上半段的“回合结束时”识别持续触发。4548、4577、4930、4931、4932、4975 的原有互斥规则及 217／4548 双向排除仍是待验证假说。触及冲突的整张组件会被排除；两张备选组件之间也不能冲突。结果不代表游戏内精确概率。

验证：使用 Node.js 运行 `test_engine.js`，会对 13 张卡及中立卡的各职业抽样检查组合规则。

## 试玩服标签核对

给 Python 提供 UnityPy 后，运行 `python inspect_event_dbf.py <试玩服的 dbf.unity3d 路径>`，可只读解析游戏文件，生成 `client_tags.json` 和 `tag-audit` 中的逐卡 CSV、汇总报告。若另有相同版本的 `CardDefs.xml`，仍可运行 `inspect_assemble_tags.py` 交叉核对。互斥编号的具体配对规则需要用试玩服中实际出现的主体、组件和可选半段验证。
